UNIDAD 1 · ABSTRACCIÓN

Clase, objeto, atributos y métodos

Clase

Es el molde o plantilla que define atributos y comportamientos.

Objeto

Es una instancia concreta de una clase, con sus propios valores.

Ejemplo

class Vehiculo { String marca; String modelo; void acelerar() { System.out.println("El vehículo acelera"); } } Vehiculo carro = new Vehiculo();

Pregunta para los estudiantes: ¿Cuál es la clase y cuál es el objeto?

La clase es Vehiculo. El objeto es carro, creado con new Vehiculo().
UNIDAD 2 · ENCAPSULAMIENTO

¿Qué significa encapsular?

El encapsulamiento consiste en proteger el estado interno de un objeto y controlar cómo se accede a sus datos.

🔒 private

El atributo no se accede directamente desde cualquier parte.

🌐 public

Permite exponer métodos u operaciones que pueden ser utilizados desde fuera.

🛡️ Control

Los métodos pueden controlar cómo se consulta o modifica el estado.

Antes vs. después

Menos control
public double saldo;
Encapsulado
private double saldo; public double getSaldo() { return saldo; }
Idea clave: encapsular no significa simplemente escribir private. Significa controlar el acceso al estado del objeto.
UNIDAD 2

Constructores

Un constructor permite inicializar un objeto cuando se crea.

public class Persona { private String nombre; public Persona(String nombre) { this.nombre = nombre; } } Persona p = new Persona("Ana");

1️⃣

Se llama al crear el objeto.

2️⃣

Tiene el mismo nombre de la clase.

3️⃣

No se declara un tipo de retorno.

En new Persona("Ana"), el constructor recibe "Ana" y la utiliza para inicializar el atributo nombre.
UNIDAD 2 · ENCAPSULAMIENTO

Getters y Setters

Son métodos utilizados para consultar o modificar atributos encapsulados.

Getter

Obtiene un valor.

public String getNombre() { return nombre; }

Setter

Modifica un valor.

public void setNombre(String nombre) { this.nombre = nombre; }

⚠️ ¿Siempre debe existir un setter?

No necesariamente. Si un dato no debe modificarse después de establecerse, se puede proporcionar solo un getter.

Ejemplo: un atributo como el año de publicación puede consultarse sin necesariamente permitir que se cambie.
UNIDAD 2

Sobrecarga de métodos

Consiste en tener varios métodos con el mismo nombre, pero con una firma diferente, por ejemplo, distinta cantidad o tipo de parámetros.

public double calcularArea(double lado) { return lado * lado; } public double calcularArea(double base, double altura) { return base * altura; }
Recuerda: Java decide qué versión utilizar según los argumentos que se pasan al llamar el método.

UNIDAD 2 · SOLID

Principio de Responsabilidad Única — SRP

La idea central es que una clase tenga una única razón para cambiar, es decir, una responsabilidad bien definida.

🚨 Detectar el problema

class Empleado { calcularSalario(); generarReportePDF(); enviarCorreo(); }

Esta clase mezcla responsabilidades diferentes.

💡 Separar responsabilidades

Empleado

Datos y cálculo del salario.

GeneradorReportePDF

Generar reportes.

ServicioCorreo

Enviar correos.

Pregunta para la clase: ¿qué tendría que cambiar si la empresa cambia el formato del PDF?
La respuesta ayuda a identificar por qué conviene separar responsabilidades.
UNIDAD 3 · RELACIONES ENTRE CLASES

Cuatro relaciones que debemos distinguir

🔗 Asociación

Una clase se relaciona con otra. Ambas pueden existir independientemente.

Idea: "se relaciona con"

↗️ Dependencia

Una clase utiliza a otra temporalmente, por ejemplo, como parámetro de un método.

Idea: "usa"

🟣 Agregación

Un todo agrupa partes que pueden seguir existiendo por separado.

Idea: "tiene un", relación débil

🔴 Composición

El todo y sus partes tienen una dependencia fuerte dentro del modelo.

Idea: "tiene un", relación fuerte

🧠 La pregunta que ayuda a distinguir agregación y composición

¿La parte puede existir y tener sentido por sí sola, separada del todo?
Sí → agregación.
No → composición.
